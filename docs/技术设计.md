## 0. 结论摘要

v0.1 交付一个**可本地运行、离线可用**的 Web 工作台：

- 4 个滑块族问题模型：水平单滑块、斜面滑块、滑块 + 长木板、传送带滑块。
- 确定性物理内核：分段常加速度 + 事件驱动，解析求解，不依赖通用物理引擎、不依赖大模型。
- 三栏界面：左参数、中场景与曲线、右 AI 助教。
- 动画、曲线、力、事件、解释来自**同一次运行**的同一份数据。
- AI 只产出**结构化修改提案**，经校验与用户确认后写入场景；无密钥时退化为离线规则解析，全部基础功能不受影响。

验收标准（v0.1 完成定义）：

1. `pnpm test` 全绿，且覆盖本文 §12 表中的精确参考值。
2. `pnpm dev` 一条命令启动界面与 AI 代理；不配置密钥时界面可用。
3. 四个模型均可编辑参数、播放、暂停、单步、重置，曲线与事件正确联动。
4. 同一场景重复运行结果逐位一致；参数变更后旧运行被标记为过期。
5. 场景可保存到 IndexedDB、可导出/导入 JSON、可导出画布 PNG。

### 1.2 v0.1 明确不做（避免范围失控）

- 拍照识题、图片理解、任意文字题自动建模（留待 v0.3，需先解决图文识别与题意校验分层）。
- 自由搭建 / 通用约束求解器 / 三维。
- 通用刚体引擎（Matter.js 等）作为标准答案来源。
- 云同步、账号体系、多人协作、课堂实时投屏。
- 多 Agent、LangGraph 等重型框架。
- 弹簧、碰撞、连接体等模型（架构预留，不在本期）。
- 移动端适配（仅保证 1280px 以上桌面浏览器的可用性）。

### 1.3 非目标但需保持的扩展点

- `ModelDefinition` 注册表：新增模型只需实现接口并注册。
- `Segment` 已有 `mode` 与 `forces` 字段，可容纳分段不同的受力结构。
- 渲染原语（line/rect/arrow/spring...）为通用二维表达，后续可扩弹簧与碰撞。
- 场景协议带 `schemaVersion`，AI 提案带 `baseRevision`，可平滑演进。

## 2. 决策记录

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| D1 | 首版覆盖 4 个滑块族模型 | 用户已定「滑块问题」；四个模型覆盖高考滑块题的主要变式，且全部可用常加速度分段解析，正确性可证 |
| D2 | 本地 Web 优先，`pnpm dev` 起服务 | 老师试用成本最低，无需部署；同时保留 Node 代理以便后续线上化 |
| D3 | TypeScript + React + Vite + Zustand + Canvas 2D + ECharts | 沿用调研建议；单人维护成本低，物理内核可脱离浏览器测试 |
| D4 | 场景文档是唯一事实来源，`revision` 单调递增 | 参数面板、AI 提案、保存/导入都走同一校验入口，避免多处状态漂移 |
| D5 | 解析分段求解，不用通用引擎 | 题目是理想化模型（库仑摩擦、刚性接触），引擎的约束近似会引入不可解释误差；解析解可给出精确参考值 |
| D6 | 单一求值入口 `stateAt(run, t)` | 动画、曲线、数值、力箭头、事件共用同一函数，从结构上杜绝「动画和曲线不一致」 |
| D7 | AI 只产出结构化提案，不直接写场景、不参与计算 | 可校验、可展示差异、可拒绝；计算永远在内核中完成 |
| D8 | 无 API 密钥可完整使用（规则解析 + 模板解释） | 备课现场可能断网；也降低首次体验门槛 |
| D9 | 存储用 IndexedDB + JSON 文件，不引入后端数据库 | 首版单机备课足够；导入导出即分享路径 |
| D10 | pnpm workspace：`packages/core` 不依赖浏览器与 React | 内核可被 Vitest、Node 脚本、未来 CLI 直接复用 |

### 3.1 目录

```text

│  ├─ src/scene/             # zod 协议、默认值、注册表
│  ├─ src/models/            # 四个模型：物理 + 渲染帧
│  ├─ src/solver/            # 分段求解、求值、采样、汇总
│  ├─ src/ai/                # 提案协议、离线规则解析、应用与差异
│  ├─ src/render/            # 场景帧类型、相机适配
│  └─ test/                  # Vitest
├─ apps/web/                 # React + Vite 界面
├─ apps/server/              # 无依赖 Node 代理（/api/ai/*）
├─ docs/技术设计.md
└─ package.json              # pnpm workspace 根
```

### 3.2 依赖方向

```text
apps/web ──→ packages/core
apps/web ──→ HTTP ──→ apps/server ──→ LLM（可选）
apps/server 不依赖 core：请求中携带由 core 生成的「能力简报」，代理保持无状态、无构建
```

### 3.3 数据流

```text
参数面板 ─┐
AI 提案 ──┼→ 校验/合并 → Scene(revision++) → 求解器 → Run(segments/events/summary)
场景导入 ─┘                                            │
                                                       ├→ Canvas 帧（stateAt）
                                                       ├→ ECharts 曲线（采样）
                                                       ├→ 事件时间轴
                                                       └→ AI 解释上下文（摘要）
```

关键约束：

- AI 请求只发送场景摘要与能力简报，不发送完整历史；解释只引用 `runId`。
- 任何 `scene.revision` 变化都会使旧 `Run` 标记过期（界面顶部提示，可保留用于对比）。
- 求解在内核同步完成（四个模型均 < 2ms），无需 Worker；架构上保留后续迁移点。

## 4. 场景协议

### 4.1 单位约定

| 物理量 | 单位 | 说明 |
| --- | --- | --- |
| 长度 / 位移 | m | 内部与显示统一 SI |
| 质量 | kg | |
| 时间 | s | |
| 速度 | m/s | 带符号，符号表示沿模型轴的朝向 |
| 加速度 | m/s² | |
| 力 | N | |
| 角度 | °（界面）/ rad（内部） | 协议中存 `angle_deg` |
| 摩擦因数 | 无量纲 | `mu_static`、`mu_kinetic` |
| 重力加速度 | m/s² | 默认 9.8，允许 10 以贴合部分教材 |

方向约定：模型轴指向「+」方向（水平向右 / 沿斜面向上 / 木板向右 / 传送带向右）。界面必须显式画出正方向。

### 4.2 Schema（zod 定义即协议）

```ts
const SceneSchema = z.object({
  schemaVersion: z.literal('0.1'),
  sceneId: z.string().min(1),
  name: z.string().min(1).max(60),
  revision: z.number().int().min(1),
  modelId: z.string(),
  params: z.record(z.string(), z.union([z.number(), z.boolean(), z.string()])),
  settings: z.object({
    duration_s: z.number().min(0.1).max(30),
  }),
  observables: z.array(z.string()),
  notes: z.string().max(500).optional(),
  createdAt: z.string(),
  updatedAt: z.string(),
});
```

校验分两层：

1. **结构层**：zod 校验字段、类型、范围外的基本合法性。
2. **模型层**：`ModelDefinition.validate(params)` 检查物理约束（如 `mu_kinetic <= mu_static`、`angle` 范围、木板长度 > 0、初速度与位置在轨道内），返回 `Issue { level: 'error' | 'warning', key?, message }`。

`error` 阻止运行与保存；`warning` 允许运行但显示在参数面板（例如 `mu_kinetic > mu_static` 时提示「动摩擦因数大于静摩擦因数，模型仍按给定值计算」）。

### 4.3 版本规则

- `revision` 从 1 开始；任何物理参数、模型、时长的变更 +1；仅改场景名不加。
- AI 提案记录 `baseRevision`；应用时若 `scene.revision !== baseRevision`，拒绝并提示「场景已变化，请重新解析」。
- `Run` 记录 `sceneRevision`；界面比较两者判断是否过期。
- 导入 JSON：`revision` 保留，`sceneId` 重新生成以避免覆盖，`name` 追加「(导入)」。

## 5. 模型接口

### 5.1 元数据

```ts
interface ParamSpec {
  key: string;
  label: string;
  unit?: string;
  group: 'object' | 'environment' | 'initial' | 'run';
  type: 'number' | 'boolean';
  default: number | boolean;
  min?: number;
  max?: number;
  step?: number;
  hint?: string;
  /** 正方向说明，例如「向右为正」 */
  axis?: string;
}

interface ModelDefinition {
  id: string;                 // 'horizontal-block'
  name: string;               // '水平面滑块'
  category: string;           // '滑块'
  summary: string;
  parameters: ParamSpec[];
  assumptions: AssumptionSpec[];
  observables: ObservableSpec[];
  /** 生成默认场景参数（深合并） */
  createScene(name?: string): Scene;

```

参数面板完全由 `parameters` 生成，因此新增模型不需要改 UI。

### 5.2 运行结果

```ts
interface BodyMotion {
  x0: number;   // t0 时刻沿模型轴的位置 m
  v0: number;   // t0 时刻速度 m/s
  a: number;    // 该阶段恒定加速度 m/s²
}

interface Segment {
  t0: number;
  t1: number;
  label: string;                      // '匀减速滑动'
  mode: string;                       // 'slip' | 'together' | 'stuck' ...
  bodies: Record<string, BodyMotion>; // 阶段内每个刚体
  forces: Force[];                    // 阶段内恒定的受力（用于画箭头与热耗散）
  heatEnd: number;                    // 截至 t1 的累计摩擦生热 J
}

interface Run {
  runId: string;
  sceneId: string;
  sceneRevision: number;
  modelId: string;
  solverVersion: string;
  duration_s: number;
  segments: Segment[];
  events: SimEvent[];
  warnings: string[];
  summary: Record<string, number | string | null>;
  createdAt: string;
}

interface SimEvent {
  t: number;
  kind: 'start' | 'stop' | 'reverse' | 'sync' | 'leave' | 'end';
  title: string;        // '滑块停止'
  detail: string;       // '速度降为 0，静摩擦可维持静止'
  bodyIds?: string[];
}
```

`Force`：

```ts
interface Force {
  id: string;
  label: string;        // '动摩擦力'
  on: string;           // bodyId
  kind: 'gravity' | 'normal' | 'friction' | 'applied';
  magnitude: number;    // N，>= 0
  dir: { x: number; y: number }; // 世界坐标单位向量（y 向上）
  heat?: { bodyId: string; relativeTo: string | 'ground' };
}
```

带 `heat` 的力参与摩擦生热积分：`heat += magnitude × |Δx_body − Δx_relativeTo|`。

### 5.3 求值

```ts
function stateAt(run: Run, t: number): {
  t: number;
  segment: Segment;
  bodies: Record<string, { x: number; v: number; a: number }>;
};
```

- 二分查找所在 `Segment`，按常加速度公式求值。
- `t` 超出 `[0, duration_s]` 时收敛到端点。
- 曲线采样、动画、单步、事件跳转全部经由此函数。

## 6. 物理模型规格

所有模型共享：`g`、库仑摩擦（`μs` 静摩擦上限、`μk` 动摩擦），物体视为质点（渲染为方块），忽略空气阻力，接触面刚性。

### 6.1 水平面滑块 `horizontal-block`

**坐标系**：x 轴水平向右为正；地面 y=0。

**参数**（7）：`mass_kg`、`gravity_m_s2`、`initial_position_m`、`initial_velocity_m_s`、`applied_force_N`、`mu_static`、`mu_kinetic`。

**受力**：重力 `mg`（向下）、支持力 `N = mg`（向上）、水平外力 `F`（+x）、摩擦力。

**运动方程**：

- 滑动中（v≠0）：`a = (F − sign(v)·μk·m·g) / m`
- 静止且 `|F| ≤ μs·m·g`：`a = 0`，静摩擦 `f = −F`（显示为「静摩擦力」，方向与 F 相反，大小 |F|）
- 静止且 `|F| > μs·m·g`：起滑，`a = (F − sign(F)·μk·m·g) / m`

**事件**：`start`（从静止起滑）、`stop`（v 降为 0 且静摩擦足够，之后不再运动）、`reverse`（v 过零但外力超过最大静摩擦，反向加速）。

**终止**：到达 `duration_s`；若滑块越过轨道端点，追加 `leave` 事件并警告（物理仍按无边界计算，仅提示画面边界）。

**参考用例**：`m=1, g=9.8, v0=4, μk=0.2, F=0` → `a=−1.96`，停止时间 `2.040816 s`，位移 `4.081633 m`（与调研文档 §10.2 一致）。

### 6.2 斜面滑块 `incline-block`

**坐标系**：s 轴沿斜面向上为正，底端 s=0；世界坐标 `(s·cosθ, s·sinθ)`。

**参数**（9）：`mass_kg`、`gravity_m_s2`、`angle_deg`（0–80）、`initial_position_m`（沿斜面，0–长度）、`initial_velocity_m_s`（向上为正）、`applied_force_N`（平行于斜面，向上为正）、`mu_static`、`mu_kinetic`、`incline_length_m`。

**受力**：重力 `mg`（竖直向下，沿斜面分量 `−mg sinθ`）、支持力 `N = mg cosθ`、沿面外力 `F`、摩擦力 `−sign(v)·μk·N`。

**运动方程**：`a = (F − m·g·sinθ − sign(v)·μk·m·g·cosθ) / m`

**静止判据**：`|F − m·g·sinθ| ≤ μs·m·g·cosθ` 时静止（包含 `tanθ ≤ μs` 的自然静止）。

**事件**：`start`（静止起滑，通常为下滑）、`stop`（速度为零且可静止，例如上行到最高点停住——需 `tanθ ≤ μs` 且外力不足）、`reverse`（上行到最高点后下滑）、`leave`（到达 s=0 或 s=L，离开斜面，终止）。

**参考用例**：`θ=30°, μs=μk=0.2, v0=0, s0=4` → `tan30°=0.577 > 0.2`，下滑 `a=−3.20259 m/s²`，到 s=0 用时 `1.5803 s`，末速 `−5.063 m/s`。

### 6.3 滑块 + 长木板 `board-block`

**坐标系**：地面 x 轴向右为正。木板左端 `xb`，滑块相对木板位置 `s ∈ [0, L]`。

**参数**（12）：`mass_block_kg`、`mass_board_kg`、`board_length_m`、`gravity_m_s2`、`mu_static_bb`、`mu_kinetic_bb`、`mu_static_ground`、`mu_kinetic_ground`、`applied_force_N`、`initial_offset_m`、`initial_velocity_block_m_s`、`initial_velocity_board_m_s`。

**受力**：

- 滑块：重力、支持力 `m1 g`、外力 `F`、板对滑块的摩擦 `f`。
- 木板：重力 + 滑块压力（`N = (m1+m2) g`）、地面支持力、滑块对板的摩擦 `−f`、地面摩擦。

**三种模式**：

1. `slip`（相对滑动）：`f = μk,bb · m1 · g`，方向与相对速度 `v_rel = v1 − v2` 相反。
   - 滑块：`a1 = (F + f_on_block)/m1`
   - 木板：`a2 = (f_on_board − f_ground)/m2`；若 `v2 = 0`，先判断地面静摩擦能否维持：`|f_on_board| ≤ μs,g·(m1+m2)g`，能则 `a2=0`（板不动），否则取动摩擦。
2. `together`（共速无相对滑动）：整体 `a = (F − f_ground)/(m1+m2)`；地面摩擦按 `v` 是否为 0 分别取动/静。
   - 需校验板对滑块的静摩擦：`f_req = m1·a − F`，若 `|f_req| > μs,bb·m1·g` 则实际上不能共速，转回 `slip`。
3. `stuck`（整体静止）：`v1=v2=0` 且地面静摩擦可托住外力。

**事件**：`start`、`sync`（`v_rel` 过零且可共速）、`stop`（共速后整体停下）、`leave`（滑块到达木板端点，滑离木板，终止）。

**参考用例**：`m1=1, m2=2, v10=6, v20=0, L=12, μk,bb=0.2, μs,g=0.1, μk,g=0.08` → 地面最大静摩擦 `2.94 N > 1.96 N`，木板不动；滑块 `a=−1.96`，`3.0612 s` 停下，位移 `9.1837 m`；摩擦生热 `18.0 J` = 初动能。

### 6.4 传送带滑块 `conveyor-block`

**坐标系**：沿传送带向右为正。带速 `vb` 恒定（可为负）。

**参数**（9）：`mass_kg`、`belt_length_m`、`belt_speed_m_s`、`gravity_m_s2`、`mu_static`、`mu_kinetic`、`applied_force_N`、`initial_position_m`、`initial_velocity_m_s`。

**受力**：重力、支持力 `N=mg`、外力 `F`、摩擦力。

**运动方程**：

- 相对滑动（`v ≠ vb`）：`f = −sign(v − vb)·μk·m·g`，`a = (F + f)/m`
- 同步（`v = vb`）：需静摩擦 `|F| ≤ μs·m·g`，此时 `a = 0`，随带匀速；否则重新滑动（`f` 取动摩擦，方向由 `F` 决定）。

**事件**：`sync`（达到带速并随带运动）、`slip`（静摩擦不足，重新滑动）、`leave`（到达带端，终止）、`start`。

**参考用例**：`vb=2, v0=0, μk=0.2, g=9.8` → `a=1.96`，`1.0204 s` 达到带速，位移 `1.0204 m`，之后匀速；`t=3s` 时 `s=4.98 m`。

## 7. 求解器

### 7.1 分段驱动

```text
state = model.init(scene)
t = 0; segments = []; events = [{t:0, kind:'start'}]
while t < duration && phaseCount < 64:
  (accel, forces, mode) = model.acceleration(state, scene)
  next = model.nextEvent(state, scene, accel)    # 模型给出最近的非平凡事件
  tEnd = min(next?.time ?? duration, duration)
  if tEnd <= t + EPS: break                      # 防抖
  segments.push({ t0:t, t1:tEnd, bodies: motionOf(state, accel), forces, mode, heatEnd })
  if next: events.push(next.event); state = next.apply(state)
  else break
  t = tEnd
```

- `EPS = 1e-9`；事件时刻的 `v` 被钳制到 0（或带速）以避免数值抖振。
- 每个模型最多 200 段；超限则写入 warning 并截断（正常物理过程远小于此）。
- 求解全程纯函数：相同 `Scene` 得到逐位相同的 `Run`（`runId` 由内容哈希生成，便于判断是否同一结果）。

### 7.2 热耗散

对每段，遍历 `forces` 中带 `heat` 的力：

```text
Δx_body     = x_body(t1) − x_body(t0)
Δx_relative = Δx_body − (Δx_counterpart 或 0)
heatEnd     = heatPrev + |F| · |Δx_relative|
```

摩擦生热的参考系必须一致：地面摩擦用「相对地面」，滑块-木板摩擦用「相对木板」。

### 7.3 采样

曲线采样 `N = 400` 个等距点 + 所有段边界 + 所有事件时刻，按时间排序去重。采样仅用于绘图；动画与读数走 `stateAt`，保证任意时刻精确。

### 7.4 汇总

`summary` 字段（供界面、AI 解释与对比表使用）：

| 字段 | 含义 |
| --- | --- |
| `stop_time_s` | 首次运动停止时间，`null` 表示未停止 |
| `final_position_m` / `final_velocity_m_s` | 终止时刻状态 |
| `total_distance_m` | 路程（各段 `|Δx|` 之和） |
| `max_speed_m_s` | 最大速率 |
| `friction_heat_J` | 摩擦生热 |
| `initial_energy_J` / `final_energy_J` | 机械能（KE + 重力势能，以初始位置为零点） |
| `energy_residual_J` | `initial − final − heat`，应接近 0，是运行时不变量自检 |

`energy_residual_J` 超过 `1e-6` 时在 UI 显示警告——这是内核自检，不是题目条件。

### 7.5 数值防护

- 静摩擦判定使用 `≤` 且带 `1e-9` 相对容差，避免 0.9999999 抖动。
- 停止判定后强制 `v = 0`、`a = 0`，不再产生新的微小段。
- 位移/速度读取保留 6 位有效数字展示，内部不截断。

## 9. AI 契约

### 9.1 提案

```ts
interface Proposal {
  id: string;
  baseRevision: number;
  intent: 'modify' | 'switch_model' | 'compare' | 'explain' | 'unknown';
  ops: Array<
    | { op: 'set_param'; key: string; value: number | boolean | string }
    | { op: 'switch_model'; modelId: string; params?: Params }
  >;
  message: string;              // 面向老师的自然语言说明
  pending: Array<{ key?: string; question: string }>;  // 待确认项，不静默补全
  warnings: string[];
  compare?: { key: string; a: number; b: number };
}
```

应用规则：

- `intent === 'unknown'`：不产生操作，只展示澄清问题。
- 每个 `set_param` 必须通过模型元数据校验（存在该参数、类型匹配、范围）；任一操作非法 → 整个提案拒绝，并说明原因。
- 只允许「其他条件不变」式的最小修改：提案只含显式操作，不隐含重置。
- `baseRevision !== scene.revision` → 标记过期，禁用「应用」。
- 应用成功后 `revision+1`，界面展示逐项 diff（旧值 → 新值）与「已重新计算」。

### 9.2 离线规则解析（默认，无需密钥）

支持的说法（中英文混合、数字可用阿拉伯数字或常见中文数字）：

| 意图 | 示例 | 处理 |
| --- | --- | --- |
| 改参数 | 「把质量改成 2 kg」「μ=0.3」「倾角 30 度」「初速度 5 m/s，向右」 | 正则匹配参数别名 + 数值 + 单位，生成 `set_param` |
| 切换模型 | 「换成斜面」「用长木板演示」 | 关键字映射到 `modelId`，保留公共参数（m、g、μ、v0），告知被忽略的参数 |
| 对比 | 「对比 μ=0.2 和 0.4」 | 生成 `compare` 计划 |
| 解释 | 「为什么停下来了」 | 基于当前 `Run` 生成模板解释（事件 + 受力 + 数值） |
| 无法识别 | 「让这个题更生动」 | `unknown` + 给出可用说法示例 |

规则解析器是**确定性**的，可作为 LLM 不可用时的降级路径，也方便写测试。

### 9.3 LLM 代理（可选）

- 端点：`POST /api/ai/propose`，请求体 `{ text, sceneBrief, capability, runBrief }`。
- 服务端持有密钥（`OPENAI_API_KEY` / `OPENAI_BASE_URL` / `OPENAI_MODEL`），前端不接触密钥。
- 提示词要求「只输出 JSON」，服务端解析失败时返回 `{ ok:false, reason }`，前端自动回退规则解析。
- 不发送完整场景历史；只发送参数、模型 id、当前运行摘要。
- 超时 20s、最大 1 次重试；错误在界面显示为「AI 服务不可用，已使用离线解析」，不阻断操作。

### 9.4 解释的边界

- 解释中出现的每个数字都来自 `Run.summary`、`events` 或参数，不凭空生成。
- 不能解释为「题目一定如此」；缺失条件进入 `pending`。
- 解释与 `runId` 绑定，卡片上显示「基于运行 #N（rev M）」。

```text
│ 待确认       │ 曲线（v/x/a/能量）            │ 输入框          │
│ 运行设置     │                               │                 │
└──────────────┴───────────────────────────────┴─────────────────┘
```

- 左栏可折叠（`Ctrl+1`），右栏可折叠（`Ctrl+2`）；中间最小宽度 520px。
- 顶栏 `运行 #N · rev M`；若 `run.sceneRevision !== scene.revision` 显示琥珀色「结果已过期」。

### 10.2 左栏

- 模型卡片：名称、一句话说明、正方向提示。
- 参数按「对象 / 环境 / 初始条件 / 运行」分组；数字输入带单位后缀，步进按参数 `step`；输入即时校验，非法值红框且不写入场景。
- 滑块（range）与数字框同步，便于课堂快速调参。
- 假设区：只读条目 + 锁图标，附「首版固定，避免隐藏假设」说明。
- 待确认区：AI 提出的歧义项，逐条可「以当前值继续」或「撤销提案」。
- 折叠的「高级」显示轨道长度等非物理关键量。

### 10.3 中间

- 画布：网格（0.5 m 细线 / 1 m 粗线）、地面、轨道/斜面/木板/传送带、物体、受力箭头、速度箭头、轨迹、事件标记。
- 左上角叠加：当前时刻、速度、加速度、摩擦状态（静/动/无）。
- 播放条：`⟲` 重置、`▶/⏸`、`⏮ −1/60s`、`⏭ +1/60s`、速度 0.25/0.5/1×、时间读数。
- 时间轴：可拖动；事件刻度可点击跳转；悬停显示事件标题。
- 事件列表：右侧或下方小列表，点击定位。
- 曲线：四个标签页，ECharts 折线；事件竖线；光标随播放移动；图例可开关；对比模式叠加 A/B 两条曲线。

### 10.4 右栏

- 顶部状态：`AI：离线规则` / `AI：已连接 <model>`；下方一行「AI 只提出修改，应用前需确认」。
- 消息流：用户气泡、助手文本、提案卡（操作 diff、警告、待确认、按钮）。
- 提案按钮：`应用到场景`（主）、`作为对比`（仅 compare/数值参数）、`忽略`。
- 快捷说法 chips：4 条，点击填入输入框。
- 输入框：`Enter` 发送、`Shift+Enter` 换行；发送中禁用。

### 10.5 关键交互细则

- 参数修改 → 300ms 防抖 → 校验 → `revision+1` → 自动重算（同步 < 2ms）→ 曲线/动画/事件全部刷新；播放位置重置到 0（可设置「保持时刻」，v0.2）。
- 应用 AI 提案 = 一次原子更新：先校验全部操作，再一次性 bump revision；失败则场景不变。
- 导入非法 JSON：拒绝并给出字段路径，不覆盖当前场景。
- 导出 PNG：按当前画布像素导出，带场景名与 rev 水印。
